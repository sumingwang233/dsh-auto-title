## 1. 一句话结论

新建会话的标题不再是你第一句话的截断，而是**等首轮助手回复结束后**，用一次轻量的辅助模型调用取一个「项目｜具体任务」形态的名字。插件是标准的 DSH profile bundle，装上即生效，卸载即回到原生行为。

## 2. 与 pi-web 的关系（二创说明）

你提到的 pi-web 给了方向和产品形态判断：**重命名动作要发生在「对话有内容之后」**，否则拿不到能区分会话的信息。

本次实现**没有逐行参考 pi-web 的代码**——它的会话模型、事件总线、provider 契约与 DSH 完全不同，抄结构没有意义。实际沿用的是三点产品结论：

| pi-web 的做法（思路） | 本插件在 DSH 上的落地 |
| --- | --- |
| 首轮结束后命名，而非首条消息 | provider 仍由 `automatic: 'first-prompt'` 触发，但**内部先等首条助手回复**再发请求 |
| 用「主题｜任务」而非裸问题 | `buildPrompt` 明确要求该格式，`normalizeTitle` 保证单行、去引号、去句末标点 |
| 命名失败不影响使用 | 任一步失败都抛错，标题服务保留上一个标题；等待超时则退化为「只看请求」命名 |

## 4. 关键设计决策

1. **抢占唯一 provider 槽位，并关掉内置那一个。** `ctx.sessionTitle` 只允许一个 provider；不关内置的 `session-title-llm`，本插件注册时会抛错。放在**本包的 patch 层**关闭，而不是让用户去改基础 bundle——卸载本包即自动恢复原生行为。
2. **先等助手回复，再命名。** 这是整个功能的价值所在；等的是 `session/event` 里的 `assistant/message`（带文本）或 `turn/end` 的 `completed`/`max-tokens`。失败或 `waitForReplyMs`（默认 120s）到点则用「只有请求」命名，**永不阻塞会话**。等待与 `messageSeqs` 都以**请求里最新一条人类消息**为锚（`all-prompts` 下即本轮触发消息，`first-prompt` 下就是唯一那条）。
3. **默认复用会话自己的路由。** `provider`/`model` 留空时取 `request.route`（会话已记录的 provider/model），所以不需要任何配置就能工作；显式配置则两个必须同时给。
4. **辅助调用不污染会话上下文。** 命名为独立 `ctx.llm.stream()` 调用，带 `sessionId` 归因与独立 `AbortSignal`；实测确认它不会抢走或中断会话正在进行的那条流。
5. **失败不写坏标题。** 空结果、模型报错、超时都抛带 `code` 的错误，服务保留旧标题；规范化后为空也抛错而不是提交空串。
6. **安静降级。** 若还有别的标题插件占着槽位，本插件只 warn 不注册，不影响 profile 启动。
7. **命名节奏可配置。** `automatic` 暴露服务支持的两种 cadence，默认 `first-prompt`（成本可控、命名稳定）；`all-prompts` 让标题跟随对话演进，代价是每条消息一次小请求。

## 6. 已知边界与后续建议

- **默认只在首轮命名一次。** 服务支持两种节奏：`'first-prompt'` 与 `'all-prompts'`（`packages/session/session-title/src/index.ts:507`），本插件用配置项 `automatic` 暴露，默认前者。想让标题跟着对话演进，设 `automatic: 'all-prompts'`——每条新消息多一次小请求，且每次都会等该轮回复。
- **每条命中的消息多一次小请求**（几百 token 进、≤96 token 出）。可 `enabled: false` 或用便宜模型覆盖。
- **可选增强**（未做，按你的「先交付可用版本」）：设置页卡片（模型选择、开关、语言）需要 client 半边，涉及 slot 注册与跨包服务，工作量约为宿主侧的两倍；需要时再排。

**2026-10-28 · v2：设置卡片 + 诊断日志 + 手动改名的可见失败**

用户反馈（原话）：「现在点击会话的三个点，可以跳出 ai 重命名选项了。但是我刚刚尝试给'接入该项目，对虚拟机中的 claw'会话进行 ai 重命名，但是没有反应」，并要求「在设置里面添加一个自动重命名的设置选项，在里面可以自行配置重命名使用的模型、供应商，并能看到错误信息日志或错误原因」。

**根因**（两条叠加，都是"静默失败"）：

1. **宿主侧**：路由按 `WebRoute` 契约注册——`handler: (req, res) => void`，**一个路径一条路由**，HTTP 方法不在路由上（`packages/host/webserver/src/index.ts:42`）。v1 的 handler 把 `(req, res)` 之后又当成有第三个 `route` 参数来判方法，于是每个请求都走到"方法不允许"或直接抛错，浏览器拿到 4xx/5xx。
2. **浏览器侧**：v1 的菜单项在请求失败时只 `setPending(null)`，没有错误面；用户看到的就是"点了没反应"。

**修法**：

- `byMethod(req, res, { POST, GET })` 按 `req.method` 分派；每个路径只注册一次。
- 失败一律回 `{ code, error }`（`empty-session` / `no-route` / `model-empty` / `invalid-config` / `method-not-allowed` …），弹窗按 code 本地化，未识别的 code 原样显示 message。
- 客户端自己也会 `POST /dsh-auto-title/log` 上报（`apply` 注册了什么、请求发出、失败原因、渲染崩溃），所以"客户端没跑起来"也能在卡片里看到。

**新增设置卡片**（`plugins.item`，与 image-gen 同一套 seat）：

| 路由 | 作用 |
| --- | --- |
| `GET /dsh-auto-title/config` | 返回 `{ effective, overrides, base, editable, settingsPath }` |
| `POST /dsh-auto-title/config` | `{ patch }` 合并保存；`{ reset: true }` 回到部署基线 |
| `GET /dsh-auto-title/log?limit=N` | 环形缓冲里最新 N 条诊断 |
| `POST /dsh-auto-title/log` | 追加一条（客户端上报）；`{ clear: true }` 清空 |

存储：`<插件目录>/settings.json`（可用 `DSH_AUTO_TITLE_SETTINGS` 改路径），每次读取都按 mtime 判断是否重载，保存后下一次命名立即生效，不用重启。

**修掉的一个自己挖的坑**：patch 原先**先写盘再校验**，一个非法值（如 `maxTitleLength: 0`）会落盘，之后每次读取都抛同一个错，卡片永久 500。现在先 `resolveConfig({...base, ...merged})` 校验，失败回 `400 invalid-config` 且不写盘。

验证：`npm test` **43/43**（core 11 + host 12 + manual 10 + settings 8 + client 2），其中 settings 用例把 `DSH_AUTO_TITLE_SETTINGS` 指到 `test/.tmp-settings.json`，覆盖合并、重置、非法值不落盘、日志记录/清空、405。

**2026-10-29 · v3.1：给「模型没有返回可用的标题」装上诊断**

真机日志已经证明链路全通（`provider registered` → `routes mounted` → 菜单行/弹窗/设置段全部注册 → 手动改名成功应用过一次），只剩模型这一环失败：

```text
route:title: using route opencode-go/deepseek-v4.1-flash (session log)
route:title: title failed for session-fb543d71…: 模型没有返回可用的标题
```

**最可能的原因**：`maxOutputTokens` 默认只有 96，而 `deepseek-v4.1-flash` 是**推理模型**——它先把预算花在 reasoning 上，96 个 token 常常在写出任何正文前就用完（`finish.kind === 'max-tokens'`，text 为空）。原来的报错只写了「没有可用标题」，把这条关键信息藏住了。

**改动：**

1. `maxOutputTokens` 默认 **96 → 512**（上限 512 → 8192）。推理模型有推理空间，短标题也够。
2. 流里单独统计 `reasoning-delta` 字符数，每次调用记一行诊断：
   `stream finish=stop text=24ch reasoning=812ch title="dsh桌面端｜重复上下文页签"`——空结果时记 `warn`，并在日志里写 `title=(empty)`。
